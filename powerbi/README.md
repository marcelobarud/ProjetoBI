# Projeto Power BI

O projeto oficial PBIP é aberto pelo Power BI Desktop em [`ProjetoBI.pbip`](ProjetoBI.pbip), com relatório PBIR e modelo semântico TMDL. A Fase 4.2 importou as sete fontes comerciais aprovadas em modo Import. A Fase 4.3 organizou essas fontes em duas fatos (`FatoPedidos`, `FatoItensPedido`) e cinco dimensões (`DimCalendario`, `DimProduto`, `DimCliente`, `DimLoja`, `DimCanal`), sem relação entre fatos. Refresh, contagens DAX, opção de data automática desligada e reabertura foram validados no Desktop. A Fase 4.4 implementou e validou 28 medidas comerciais. A Fase 4.5A centralizou-as em `_Medidas`; essa tabela é o local oficial para novas medidas DAX, organizadas em Display Folders. A validação visual confirmou a tabela `_Medidas` com sete pastas e nenhuma medida nas fatos; salvar, fechar e reabrir o PBIP foi concluído sem erro. Consulte [`../docs/powerbi/phase-4.2-connection-and-model-foundation.md`](../docs/powerbi/phase-4.2-connection-and-model-foundation.md), [`../docs/powerbi/phase-4.3-commercial-star-model.md`](../docs/powerbi/phase-4.3-commercial-star-model.md), [`../docs/powerbi/phase-4.4-commercial-dax-measures.md`](../docs/powerbi/phase-4.4-commercial-dax-measures.md) e [`../docs/powerbi/phase-4.5a-measures-centralization.md`](../docs/powerbi/phase-4.5a-measures-centralization.md).

## Fluxo de trabalho

1. Abra `ProjetoBI.pbip` no Power BI Desktop para trabalhar no projeto. A fonte `projeto_bi` usa a role read-only `projetobi_pbi_ro` e modo Import. As únicas fontes operacionais permitidas nesta camada são `sales.sales_orders`, `sales.sales_order_items`, `catalog.products`, `catalog.categories`, `crm.customers`, `core.stores` e `sales.sales_channels`.
2. Use o Desktop para criar ou alterar o relatório e o modelo semântico. Salve pelo próprio Desktop para que as definições PBIR e TMDL permaneçam consistentes.
3. Abra o repositório no VS Code/Codex para revisar diferenças textuais e documentação. As definições ficam em `ProjetoBI.Report/definition/` (PBIR) e `ProjetoBI.SemanticModel/definition/` (TMDL).
4. Se uma definição textual for alterada externamente, revise o diff e reabra/atualize o projeto no Desktop para validar antes de commit.
5. Versione o `.pbip`, as pastas `.Report` e `.SemanticModel` e seus arquivos de definição. A pasta `.pbi/` guarda cache e estado local do Desktop e é ignorada pelo Git.

Não coloque senhas, tokens ou connection strings com credenciais nas definições do projeto. A credencial read-only está guardada no Windows Credential Manager local. As consultas da Fase 4.3 projetam a data local explicitamente no PostgreSQL e propagam as chaves conformadas do pedido aos itens por uma junção pela chave única do pedido. Os grãos de pedido e item permanecem separados. As 28 medidas da Fase 4.4 agora pertencem à tabela `_Medidas`. Todas as medidas futuras devem ser criadas nessa tabela, agrupadas por Display Folders temáticas, com declaração e expressão em linhas separadas e indentação TMDL válida; preserve descrições, formatos e nomes consistentes e valide as alterações no mecanismo semântico. Após salvar, confira novamente o TMDL: na Fase 4.5A.1, o Desktop reformatou oito expressões simples para a linha da declaração. Margem, COGS e dashboards estão fora do escopo atual.
